# 税后收入计算 · 使用说明

> 项目：aftertax（北京五险一金及个税计算，2026 年，累计预扣法）
> 更新日期：2026-09-17

## 1. 项目简介与目录结构

本项目按中国个税**累计预扣法**，根据每月税前工资、五险一金个人缴纳部分和专项附加扣除，
计算每月应预扣个税与税后到手收入，并与实际工资单核对。

| 文件 | 说明 |
|---|---|
| `税后收入计算_表格版.py` | **推荐使用的表格版脚本**。自身不含任何工资数据，数据从 xlsx 读取，结果写回 xlsx 新增列 |
| `工资表_模板.xlsx` | 脱敏示例模板，演示 xlsx 的格式要求（数据均为虚构） |
| `工资表.xlsx` | 你维护的真实数据文件（已被 `.gitignore` 排除，不会入仓库） |
| `.gitignore` | 排除真实数据与旧脚本，防止敏感内容进入 Git |
| `docs/使用说明.md` | 本文档 |
| `税后收入计算.py` | 旧版控制台脚本，**代码中硬编码了真实工资数据，不要分发**（已被 .gitignore 排除） |

## 2. 环境要求与运行方式

- Python 3.6+；表格版需要 `openpyxl`：`pip install openpyxl`（当前机器已装 3.1.5）
- 运行：

```powershell
cd <项目根目录>
python -X utf8 税后收入计算_表格版.py            # 默认读同目录“工资表.xlsx”
python -X utf8 税后收入计算_表格版.py 其他表.xlsx  # 或显式指定文件路径
```

脚本不联网，只读写你指定的这一个 xlsx 文件。`-X utf8` 仅防中文乱码，可省略。

## 3. 表格版快速上手

1. 复制 `工资表_模板.xlsx` 为 `工资表.xlsx`（或直接在自己的工资表上操作）；
2. 按第 4 节的格式在 xlsx 中维护每月数据（第 1 行表头 + 每行一个月）；
3. 运行脚本；结果自动追加为 G 列起的 12 个新列；
4. 看控制台简报：共几个月、结果写在哪些列、哪些月份与工资单不一致。

## 4. xlsx 输入格式（必需列）

第 1 行为表头（列顺序任意，按名称识别；表头多余空格不影响）：

| 列名 | 含义 | 数据来源 |
|---|---|---|
| 月份 | 当年第几个月（1-12） | 工资条 |
| 本月税前收入 | 本月税前工资 | 工资条“税前收入” |
| 累计税前收入 | 本年累计税前收入 | 个税 APP / 工资条“累计收入” |
| 实际个税 | 本月实际被预扣的个税 | 工资条“本月个税” |
| 累计专项附加扣除 | 本月申报的**累计**专项附加扣除 | 申报口径；中途取消后填 0（不自动累计） |
| 每月五险一金 | 当月五险一金个人缴纳部分 | 工资条（逐月可不同） |

数据从第 2 行开始，"月份"列为空即视为数据结束。所有单元格须为数值。

**奖金场景说明**：若某笔钱（如模板中 4 月的 500 元）进了"累计税前收入"但未计入任何
"本月税前收入"，属正常现象，脚本会在"累计收入差异"列如实展示差额，计算仍以申报累计值为准。

## 5. 输出列说明（自动追加/原地更新）

脚本把下列结果写为新增列。重跑时**按表头名原地覆盖**这些列，不会重复追加；输入列一律不动、不再回显。

| 输出列 | 含义 |
|---|---|
| 累计减除费用 | 5000 × 月份 |
| 累计五险一金 | 每月五险一金 × 月份 |
| 累计收入差异 | 累计税前收入 − 逐月税前收入之和（奖金等未拆月款项，见第 4 节） |
| 累计应纳税所得额 | 核心中间量，≤0 时按 0 |
| 适用税率 / 速算扣除数 | 按第 7 节税率表查档 |
| 累计应纳税额 | 累计应纳税所得额 × 税率 − 速算扣除数 |
| 上月累计已纳税 | 上月末的累计应纳税额 |
| 本月应纳税额(计算) | 累计应纳税额 − 上月累计已纳税（不为负） |
| 与工资单差异 | 计算值 − 实际个税，**应为 0.00**；不为 0 说明输入或扣除规则与实际不符 |
| 税后收入(计算) / (实际) | 本月税前 − 五险一金 − 本月个税（分别用计算/实际个税） |

口径提示：税后收入 = 到手现金；公积金个人部分虽当月扣除但仍进入个人账户，按"总权益"口径可自行加回。

## 6. 计算逻辑（累计预扣法）

```
累计应纳税所得额 = 累计税前收入 − 5000×月数 − 累计五险一金(个人) − 累计专项附加扣除
累计应纳税额   = 累计应纳税所得额 × 适用税率 − 速算扣除数
本月应纳税额   = 累计应纳税额 − 之前月已纳税额（<0 取 0）
本月税后收入   = 本月税前收入 − 本月五险一金 − 本月应纳税额
```

## 9. ⚠️ 隐私与数据安全

- 表格版实现了**数据与代码分离**：脚本可放心分享，真实数字只存在于你的 xlsx 中；
- `.gitignore` 已排除：所有 `*.xlsx`（真实数据）与 `税后收入计算.py`（旧版硬编码）；`工资表_模板.xlsx` 为脱敏示例，允许入库；
- **旧 Git 历史（16 个提交）中仍含真实工资数字**（各版本代码与部分提交说明中直接写有月度工资、税费等金额）。仓库当前仅在本地、无远程，尚未外泄；若要发布到 GitHub，必须按第 10 节重建历史；
- 向他人发代码、上传网盘、粘贴给在线工具前，确认附件里不含真实 `工资表.xlsx` 与旧脚本。

## 10. 发布到 GitHub（只保留新脚本）

旧历史的提交说明本身带工资数字，无法靠"新提交不含敏感文件"清除，因此推荐**重建干净历史**（约 1 分钟）：

```powershell
cd <项目根目录>

# 1) 删除含敏感数据的旧历史（不可恢复，确认无需保留后执行）
Remove-Item -Recurse -Force .git

# 2) 重新初始化，只提交允许入库的文件
git init
git add 税后收入计算_表格版.py 工资表_模板.xlsx docs/使用说明.md .gitignore
git commit -m "init: 表格版税后收入计算（不含任何工资数据）"

# 3) 在 GitHub 网页上创建空仓库（不要勾选自动生成 README），然后：
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

要点：

- `.gitignore` 生效后可直接 `git add .`，但首次建议如上显式列文件并 `git status` 复核；
- 推送前自查：`git ls-files` 应只有 4 个文件；
- 推送后抽查历史是否干净：`git log --all -p | Select-String '\d{5,}\.\d{2}'`（搜索所有带小数的金额样式，新历史中应无输出。注意：不要像旧仓库那样把真实金额写进提交说明或随仓库发布的文档里）；
- 之后每月更新 `工资表.xlsx` 不会被误提交（已被忽略）。

（备选方案：若想保留提交历史再用 `git filter-repo` 改写历史与提交说明，成本高、易遗漏，不推荐。）

## 11. 已知限制

- 仅处理工资薪金累计预扣场景；年终奖单独计税、股权激励不在范围内；
- 五险一金按你填入的数值×月数计算，未内置基数上下限校验；
- 个人养老金、企业年金等其他扣除未纳入（可折算进"累计专项附加扣除"近似处理，但口径不同需谨慎）；
- 结果列与输入列同表存储：请勿手工改动 G 列起的计算列，重跑会被覆盖。
